quant
=====

The ``quant`` command takes a collated RAD file and performs feature (e.g. gene) quantification, outputting a sparse matrix of de-duplicated counts as well as a list of labels for the rows and columns.  The ``quant`` command takes an input directory containing the collated RAD file, a transcript-to-gene map, an output directory where the results will be written, and a "resolution strategy" (described below).  Quantification is multi-threaded, so it also, optionally, takes as an arguments the number of threads to use concurrently.

The transcript-to-gene map (provided using the ``-m`` or ``--tg-map`` option) should be either:

1. A three-column (headerless) tab-separated file where the first column contains a target name, the second column contains the corresponding gene feature to which this target belongs and the third column contains either ``S`` or ``U``, with ``S`` denoting the corresponding feature should be attributed to the spliced status of its parent gene and ``U`` denoting that it should be attributed to the unspliced status of its parent gene.

2. A two-column (headerless) tab-separated file where the first column contains a transcript name and the second column contains the corresponding gene name for this transcript.

The ``quant`` command exposes a number of different resolution strategies.  Note: If you are providing a three-column transcript-to-gene map, and hence quantifying in Unspliced/Spliced/Ambiguous (USA) mode, then only the ``cr-like`` and ``cr-like-em`` resolution modes are currently available. The different UMI resolution strategies are:

* ``cr-like`` : This strategy is like the one adopted in cell-ranger, except that it does not first collapse 1-edit-distance UMIs.  Within each cell barcode, a list of (gene, UMI, count) tuples is created. If a read maps to more than one gene, then it generates more than one such tuple.  The tuples are then sorted lexicographically (first by gene id, then by UMI, and then by count).  Any UMI that aligns to only a single gene is assigned to that gene.  UMIs that align to more than one gene are assigned to the gene with the highest count for this UMI.  If there is a tie for the highest count gene for this UMI, then the corresponding reads are simply discarded.

* ``cr-like-em`` : This strategy is like ``cr-like``, except that when a UMI has genes to which it matches with equal frequency, rather than discard the UMIs, the genes are treated as an equivalence class, and the counts for each gene are determined via an expectation maximization algorithm.

* ``parsimony-em``/``full`` : This implements the algorithm described in the alevin_ paper.  Briefly, it builds a graph among the set of reads that align to an overlapping set of transcripts and that have similar (within an edit distance of 1) UMIs.  It then attempts to find a parsimonious cover for this graph using the fewest number of possible transcripts.  If a unique parsimonious cover is found, then the (deduplicated) reads are assigned directly to the genes that yield the most parsimonious cover. If multiple equally-parsimonious covers exist, then the reads are considered multi-mapping at the gene level and they are probabilistically resolved using an expectation maximization (EM) algorithm. 

* ``parsimony`` : This strategy is the same as "full", except that it does *not* probabilistically resolve reads that remain as gene-multimapping after applying the parsimony criterion.  Instead, reads that do not have a unique most-parsimonious assignment are discarded. 

* ``parsimony-gene`` : This strategy is the same as ``parsimony`` above, except that mappings of UMIs to transcripts are projected to their corresponding gene *before* the relevant graph (Parsimonious UMI Graph) is constructed.  Thus, the vertices of the graph consist of sets of gene labels rather than sets of transcript labels.  This method may be less precise than the ``parsimony`` method (i.e. may wrongly group together UMIs that arise from different transcripts within the same gene), but it simultaneously likely to be more robust to misannotation or incomplete annotation (e.g. incomplete UTR annotation).

* ``parsimony-gene-em`` : This strategy is the same as ``parsimony-above`` above, except that, like ``parsimony-em`` any graphs that exhibit a multi-gene cover will have the multimapping resolved probabilistically with an EM algorithm..

* ``trivial`` : This strategy does not search for 1 edit-distance neighbors of UMIs.  Instead, it first discards any reads that multi-map at the gene level.  The reads that remain then all map uniquely to a single gene.  These reads are deduplicated by (exact) UMI, and the number of distinct UMIs mapping to each gene are taken as that gene's count in the current cell. **Note**: This resolution strategy is not available in USA mode.

Additionally, this command can optionally take the following flags (note that not all resolution strategies are compatible with these flags):

* ``-d, --dump-eqclasses`` : This flag will cause a gene-level, UMI-deduplicated, equivalence class counts file to be written to the output directory in addition to the gene-level count matrix.  This can be used for subsequent analyses where gene-ambiguous reads have been neither resovled nor discarded.

* ``-b, --num-bootstraps`` : This flag will cause bootstrap inferential replicate information to be written to the output directory.  This provides a measure of the inferential uncertainty in the gene-level estimates provided by ``alevin-fry`` when run with a method using the EM algorithm for gene-level abundance estimation.  This information can be used with downstream testing, like differential expression testing using swish.  This flag is only meaningful with the ``cr-like-em`` or ``full`` resolution modes.

* ``--summary-stat`` : This flag will write the summary statistics of the bootstrap replicates (i.e. the mean and variance of the inferential replicates).  This provides the most important information for uncertainty-aware downstream analysis, while requiring much less storage space than the full bootstrap replicate information.  This flag is only meaningful when ``--num-bootstraps`` is meaningful.

* ``--quant-subset <SFILE>`` : This optional argument provides a file containing list of barcodes to quantify (one barcode per line, written as a string), those not in this list will be ignored during inference and will not appear in the output quantification matrix.  If this argument is not provided, then all of the original barcodes will be quantified.

* ``--use-mtx`` : This flag will cause the output to be written in matrix market coordinate format (which is the default).

* ``--use-eds`` : This flag will cause the output to be written in EDS format rather than in matrix market format.

* ``--model-truncation`` : Fit a positional likelihood for 3'-anchored, potentially 5'-truncated long reads independently for each cell. The model is fit to the deduplicated molecules produced by ``parsimony-em`` and replaces their transcript assignments with posteriors under the fitted model. Gene counts are the sums of these posteriors over each gene's transcripts (counts below 0.01 are set to 0, as in the EM); the gene-level EM is not run, since the posteriors already include the model's transcript abundances. In USA mode the gene-level EM still runs on the posteriors. It uses the oarfish truncation-mixture model: each molecule is a mixture of 3'-anchored, 5'-anchored, full-length and uniformly placed reads, with learned read-length laws and end-gap kernels, estimated jointly with the transcript abundances. The EM follows oarfish: the parameters are re-estimated together with the abundances until they freeze, after which the abundances continue under fixed weights with SQUAREM acceleration, stopping at a relative change below 1e-3 or 1000 iterations. This option requires long-read alignment probabilities and ``--resolution parsimony-em``; it cannot be combined with ``--coverage-model``, ``--coverage-dedup``, a non-default ``--end-model``, bootstrapping, or ``--true-umi-mode=direct``.

* ``--truncation-interval-mode all|union|none`` : Selects how multiple alignment intervals for one molecule/transcript contribute when ``--model-truncation`` is enabled. ``all`` (the default) treats intervals as separate positional alternatives with the transcript's prior probability divided evenly among them. ``union`` merges overlapping/adjacent intervals and uses one outer span from the leftmost start to the rightmost end; for disjoint intervals, this span includes the intervening gap. ``none`` ignores the intervals: no positional likelihood, only the alignment-score prior and the abundances (a control for what the positional model adds; equivalent to ``--truncation-positional-power 0``).

* ``--truncation-params cell|global`` : Selects where the truncation model's parameters (mixture weights, read-length laws and end-gap kernels) are estimated when ``--model-truncation`` is enabled. ``cell`` (the default) estimates them separately in each cell, together with that cell's transcript abundances. ``global`` estimates them once, before any cell is quantified, in an extra pass over the input that resolves every cell's molecules as quantification does and fits one set of parameters shared by all cells (each cell keeping its own abundances); the fit stops when the parameters freeze. Every cell's EM then estimates only its abundances with these parameters fixed (100 plain EM steps, then SQUAREM acceleration), as oarfish does after estimating its parameters on a read sample. The global parameters are written to ``truncation_model_global.tsv``. The global fit holds the molecules of all the cells it uses in memory.

* ``--truncation-global-cells N`` : With ``--truncation-params global``, estimates the parameters from about ``N`` cells spread evenly through the input (every k-th cell) instead of from all cells, to reduce the memory and time of the global fit. As oarfish does on a read sample, the fit's log-likelihood freeze threshold is scaled by the sample's share of the reads, so the sample freezes where a fit to all cells would. The default, ``0``, uses all cells.

* ``--truncation-length-law marginal|conditional`` : How the read-length laws depend on the transcript's length. ``marginal`` (the default, the oarfish model) uses one law per mixture component for all transcripts. ``conditional`` uses one law per component and transcript-length class (class edges at 300, 500, 700, 900, 1100, 1400, 1700, 2000, 2500, 3000, 4000, 5500 and 8000 nt).

* ``--truncation-end-kernels mixed|absolute`` : The end-gap kernels. ``mixed`` (the default, the oarfish model) has an absolute part and a part relative to the transcript's length. ``absolute`` keeps the absolute part only. The relative part gives a short transcript a density of order ``rho / length`` at every gap, which explains truncated reads of a long isoform as censored full-length reads of a shorter one; ``absolute`` avoids that.

* ``--truncation-abundance cell|global|shrink`` : Where each cell's transcript abundances come from; ``global`` and ``shrink`` require ``--truncation-params global``. ``cell`` (the default) uses each cell's own EM. ``global`` estimates one abundance per transcript from the molecules of all cells (per group with ``--truncation-groups``), and each cell's molecules take their posteriors under it. ``shrink`` runs each cell's own EM with Dirichlet pseudo-counts ``k * n(locus) * share(t)`` on every candidate ``t``, where ``share(t)`` is ``t``'s pooled share of its locus and ``n(locus)`` the cell's molecules in that locus, so a cell keeps its own isoform usage where its molecules show it and falls back on the pooled shares where they do not.

* ``--truncation-shrink K|auto|auto-gene`` : The strength ``k`` of the pooled prior with ``--truncation-abundance shrink``. The default, ``1``, gives the pooled shares the weight of the cell's own molecules in each locus; ``0`` is the cell's own estimate and a large ``K`` the pooled shares. ``auto`` estimates the strength from the data instead: the variation between cells in isoform shares among the molecules with one candidate transcript sets a number of pseudo-molecules per locus, ``alpha``, the same in every cell (reported in the log and as ``PriorAlpha`` in ``truncation_model_global.tsv``). With no variation beyond sampling, ``alpha`` is infinite and every cell takes the pooled shares; otherwise a cell's own ``n`` molecules of a locus weigh ``n / (n + alpha)`` against them, so cells with many molecules of a gene keep their own isoform usage. ``auto-gene`` estimates one strength per gene (it needs ``--truncation-genes``), shrunk toward the common one with the weight of about 1,000 molecule pairs: a gene whose isoform shares vary between cells more than sampling allows gets a weak prior and keeps each cell's own usage, while the rest pool fully; the log reports how many genes got a finite strength.

* ``--truncation-genes FILE`` : With ``--truncation-abundance shrink``, a ``transcript<TAB>gene`` file (no header; names are matched as written or without their version suffix). The pooled prior then acts within genes instead of within loci, the connected sets of candidate transcripts, which can merge many genes; with ``--truncation-shrink auto`` the strength is estimated from isoform shares within genes, so that differences in gene expression between cells are not read as differences in isoform usage.

* ``--truncation-positional-law mixture|four-param`` : The truncation model's positional law. ``mixture`` (the default) is oarfish's four-component mixture. ``four-param`` is the earlier four-parameter model (a full-length fraction, a 5' stop rate, a 3'-anchored fraction and a 3' decay), run with the same EM, freezing, ``--truncation-params`` and ``--truncation-abundance`` options as the mixture, so it can be fitted per cell or from all cells and used with pooled or shrunk abundances. Its parameters are reported in the ``FourFullLength``, ``FourStopRate``, ``FourThreePrime`` and ``FourDecay`` columns of the model files.

* ``--coverage-source cell|global`` : Where ``--coverage-model`` and ``--coverage-dedup`` take their coverage from. ``cell`` (the default) uses each cell's own molecules. ``global`` accumulates the deduplicated molecules of all cells (every k-th with ``--truncation-global-cells``) in a pass before quantifying, so that a transcript's coverage comes from thousands of molecules rather than a handful; the per-bin probabilities are computed as for a cell. With ``--model-truncation`` the coverage models may now be combined with the truncation model: ``--coverage-model`` multiplies each molecule's candidate priors by their coverage probability before the positional model (with either source), and ``--coverage-dedup --coverage-source global`` puts the global coverage into the alignment probabilities before deduplication. Pooled quantification with a coverage model is therefore ``--model-truncation --truncation-interval-mode none --truncation-params global --truncation-abundance global --coverage-model --coverage-source global`` (positions ignored, abundances pooled, coverage from all cells), or the same with ``--coverage-dedup``.

* ``--junction-likelihood`` : With ``--model-truncation --truncation-params global`` and ``--junction-gtf``, learns from the one-candidate molecules of all cells where reads start relative to the splice junction before them (the transcript's start counting as one), on log-spaced distance bins, and multiplies each interval's prior by that probability normalized over every start position of its transcript. Unlike ``--junction-model``, whose weight is not normalized and favours the isoform with the shortest extension before the read, this compares like a likelihood across isoforms. The mixture already models the 5' end, so use it with ``--truncation-interval-mode none`` to test the law on its own.

* ``--truncation-groups FILE`` : With ``--truncation-abundance global`` or ``shrink``, pools abundances within groups of cells instead of over all cells. ``FILE`` has ``barcode<TAB>group`` lines (no header); unlisted barcodes form one more group.

* ``--truncation-group-shrink K|auto|auto-gene`` : With ``--truncation-groups``, pulls each group's pooled isoform shares toward the shares of all cells: the group's pooled EM becomes a MAP with pseudo-molecules per locus distributed as the all-cell shares, so that a small group follows all cells where its own molecules are few and its own usage where they are many. ``0`` (the default) pools the groups independently; ``K`` gives every locus ``K`` pseudo-molecules. ``auto`` estimates the strength from the groups' own fits: for each locus the deviance of each group's pooled shares against the all-cell shares over the group's molecules (ambiguous ones included) is compared with its chi-square null; a locus whose deviance exceeds the null by four standard deviations keeps each group's own shares with a strength set by the excess, and every other locus takes the shares of all cells (an infinite strength). ``auto-gene`` does the same with genes as the loci (it needs ``--truncation-genes``), so that the loci that merge genes through shared candidates do not spread one gene's difference over its neighbours. The log reports how many loci or genes differ and the median strength; ``GroupPriorBeta`` in ``truncation_model_global.tsv`` is that median, infinite when nothing differs. Groups that differ in a few hundred genes, as cell types do, lose nothing in the other genes this way, while independent pooling (``0``) makes every small group noisier than the whole.

* ``--truncation-discover-groups [GENES]`` : With ``--truncation-abundance global`` or ``shrink``, finds the groups of cells that share isoform usage from the data, in place of a ``--truncation-groups`` file, in the pass that fits the global parameters (every cell must be in that pass, so not with ``--truncation-global-cells``). Per gene with several isoforms, a cell's molecules with one candidate transcript are multinomial around the isoform shares of its group. The cells are split by bisecting: each leaf's molecules are thinned at random into four parts; the first two give the residual features ``(x - n phi) / sqrt(n phi (1 - phi))`` on the genes whose usage varies between the leaf's cells beyond sampling, and the candidate splits (k-means and Ward clusters of the leading 20 singular vectors of the residuals for several numbers of clusters, and the tails of each component; each cluster against the rest); the third ranks the candidates by the held-out likelihood of its molecules; the fourth confirms the best one against five random sides of the same size. A side's shares are its counts shrunk toward the leaf's with a strength per gene estimated from how much the two sides differ beyond sampling, as ``--truncation-group-shrink auto-gene`` does, so that a small side is penalized only on the genes where it does differ. A split is kept when its confirmation gain beats the best random side by 20 nats in total and 0.02 nats per cell of the leaf; no side may hold fewer than 8 cells, and the bisection stops at depth 6. Finally each cell moves to the group whose shares fit all its molecules best, until none moves. Without any accepted split every cell is in one group: the pooled model. ``GENES`` is a ``transcript<TAB>gene`` file (no header; names are matched as written or without their version suffix) the discovery takes its genes from; it is needed when the ``-m`` map does not group transcripts into genes, as a transcript-to-transcript map does not, and the run stops before quantifying if no gene has two transcripts. Unlike ``--truncation-genes`` it leaves the loci the pooled prior acts within alone. The discovery is deterministic (a fixed seed; the number of threads does not change its result), the log reports every attempted split, and the groups are written to ``truncation_groups.tsv`` (``barcode<TAB>group``), which a later run can take as ``--truncation-groups``. ``scripts/truncation_groups.py`` runs the same procedure on a ``--truncation-dump``.

* ``--truncation-preset NAME`` : A named configuration of the truncation model's options; it implies ``--model-truncation``, and a truncation option given explicitly keeps its value. ``recommended`` is the configuration that did best across our evaluations (see below): ``--truncation-params global --truncation-abundance shrink --truncation-shrink 1 --truncation-end-kernels absolute --truncation-positional-power 0.5 --truncation-group-shrink auto``, with ``--truncation-discover-groups`` unless ``--truncation-groups`` is given.

* ``--truncation-dump DIR`` : With ``--truncation-params global``, writes every cell's molecule counts per candidate transcript to ``DIR/unique_counts.tsv.gz`` (``barcode``, ``transcript``, ``unique``: molecules whose only candidate is the transcript, ``candidates``: molecules with it among their candidates), for analyses of isoform usage across cells, such as finding groups of cells with the same usage for ``--truncation-groups``: ``scripts/truncation_groups.py <dump dir> <transcript-to-gene file> <groups file>`` splits the cells by usage as ``--truncation-discover-groups`` does within a run and writes a ``--truncation-groups`` file; on cells that share usage it writes one group.

* ``--truncation-oracle FILE`` : For evaluation on simulated data: a ``transcript<TAB>barcode<TAB>count`` file (a header line is skipped; names are matched as written or without their version suffix; barcodes as alevin-fry writes them) of true per-cell abundances, used as each listed cell's fixed abundances in place of the pooled ones. Requires ``--truncation-abundance global``; unlisted cells keep the pooled abundances. The assignment under the true abundances bounds what any choice of abundances can achieve with the same positional model. The abundances are held densely, cells times transcripts.

* ``--truncation-positional-power P`` : The power each molecule's positional likelihood is raised to in its weight. ``1`` (the default) is the model as it stands, ``0`` ignores positions, and values between temper the positional evidence.

* ``--truncation-calibrate-power`` : With ``--truncation-abundance global`` or ``shrink``, chooses the power from the data instead of ``--truncation-positional-power``: the power in ``[0, 2]`` that best predicts, from position and pooled abundance, the transcript of molecules whose alignment-score prior already puts at least 0.99 on one candidate (golden-section search, two rounds with the abundances refit in between). The chosen power and its log-likelihood curve are logged. Use it as a diagnostic: on 3'-anchored data the alignment-settled labels can be wrong, which biases the estimate low.

* ``--truncation-min-share EPS`` : After the fit, drops each molecule's transcript shares below ``EPS`` (its largest share is always kept) and renormalizes the rest. The default, ``0``, keeps every share.

* ``--truncation-sample-below EPS`` : After the fit, gives the combined mass of each molecule's transcript shares below ``EPS`` to one of them, drawn with probability proportional to its share. ``EPS = 1`` reports every molecule whole, under one transcript drawn from its posterior, so per-cell counts are integers. The draw keeps each transcript's expected count, so sums over cells are unbiased, while a cell's counts no longer spread fractions of a molecule over transcripts it does not express. Each draw's uniform number is fixed by the molecule's (equivalence class, UMI) vertices, so reruns give the same counts. The default, ``0``, keeps every share.

For long-read single-cell data, the configuration that performed best across our evaluations (four simulated ONT and PacBio data sets, two simulations with cell types that differ in isoform usage, and the eight lung cancer cell lines on ONT and PacBio against salmon on matched bulk short reads) is the cell prior inside a group prior at positional power 0.5: positional parameters pooled over all cells with absolute end kernels, the positional likelihood raised to the power 0.5, each cell's abundances shrunk toward the pooled isoform shares of its group with one pseudo-molecule per molecule, groups of cells found from the data, and each group's own shares kept only in the loci where the groups differ beyond sampling. It is first or within 0.007 of first on every truth, and ahead of oarfish, kallisto, isosceles and bambu on correlation, error and bias on both platforms. ``--truncation-preset recommended`` sets it:

``--resolution parsimony-em --truncation-preset recommended --truncation-discover-groups <transcript-to-gene file>``

The gene file is needed when ``-m`` is a transcript-to-transcript map. The same configuration at power 1 (``--truncation-positional-power 1``) is best against salmon TPM on the cell lines but gives the majority usage a larger share of a differing cell type's molecules in the cell-type simulations; pooled abundances without the cell prior (``--truncation-abundance global --truncation-positional-power 1``) are best on simulations whose cells share one isoform usage.

There are also a few flags that are not immediately exposed:

* ``--umi-edit-dist <EDIST>`` : This option takes a parameter that sets the Hamming distance within which potentially colliding UMIs will be considered for correction.  With resolution modes ``parsimony``, ``parsimony-em``, ``parsimony-gene`` or ``parsimony-gene-em`` the valid values are 0 and 1 (and the default is 1).  With other resolution modes, the default (and currently the only supported value) is 0.
 
* ``--large-graph-thresh <NVERT>`` : This option takes a parameter that sets the order (number of nodes) of a PUG above which an alternative (faster) resolution strategy will be applied.  This option only has an effect for ``parsimony``, ``parsimony-em``, ``parsimony-gene`` or ``parsimony-gene-em`` resolution modes.  The default value is 1000.

output
------

The output of the ``quant`` command consists of 5 files: ``quants_mat_rows.txt``, ``quants_mat.mtx`` (or ``counts.eds.gz`` if run with the ``--use-eds`` flag), ``quants_mat_cols.txt``, ``quant.json``, and ``featureDump.txt``.  The ``quant.json`` file contains information about the quantification run, such as the method used for UMI resolution.  The ``featureDump.txt`` file contains cell-level information designed to be useful in post-quantification cell filtering (better determining "true" cells from background, noise, doublets etc.).  The other three files all correspond to quantification information.

When ``--model-truncation`` is enabled, ``truncation_model.tsv`` is also written in the output directory. With ``--truncation-params global``, each row repeats the global parameters, ``ParamsFrozenAtIteration`` is ``0`` and ``FreezeReason`` is ``global``; ``truncation_model_global.tsv`` holds the global parameters in the same columns, followed by ``Cells`` and ``Molecules`` (how many the fit used), ``Iterations``, ``ParamsFrozenAtIteration`` and ``FreezeReason`` of the global fit. It has one row per cell, identified by barcode, with the fitted mixture weights (``P3Anchored``, ``P5Anchored``, ``PFullLength``, ``PUniform``), mean read lengths of the three length laws, the relative weight (``Rho``) and absolute gap mass (gap 0, 1-15, 16-255, 256+) of the 3' and 5' end kernels, number of molecules used, number of EM iterations, ``ParamsFrozenAtIteration`` (the iteration after which the truncation parameters stopped being updated, or ``NA`` if they never froze), ``FreezeReason`` (which test froze them over the three consecutive iterations that did: ``params`` if the parameters moved by less than 1e-6 in each, ``loglik`` if the log-likelihood rose by less than 1 nat in each, ``both`` if both held in each, ``mixed`` if each passed one test or the other but neither held throughout, or ``NA`` if they never froze), a ``Converged`` boolean, and ``FitStatus``. ``Converged`` is ``true`` only if the model met its abundance and parameter convergence criteria before the 1000-iteration limit. ``FitStatus`` distinguishes a converged fit, reaching the 1000-iteration limit, no positional evidence, or no data (zero iterations and initial parameter values). Check ``FitStatus`` when interpreting parameters: a cell with no positional evidence can converge numerically without providing evidence to estimate the truncation parameters. The last column, ``MixedIntervalMolecules``, counts molecules whose candidate transcripts include some with an alignment interval and some without (for example, a transcript recorded with length 0). Transcripts without an interval carry no positional likelihood, so within such a molecule they are strongly favored; this should be 0, and a warning is logged for any cell where it is not. With ``--truncation-discover-groups``, ``truncation_groups.tsv`` lists each cell's group (``barcode<TAB>group``, the groups named ``L0``, ``L1``, ...).

If ``quant`` was executed in USA mode, then the resulting count matrix will be of dimension ``C``x``3G`` where ``C`` is the number of quantified cells (barcodes) and ``G`` is the number of genes.  This is because, in USA mode, ``alevin-fry`` quantifies the UMI count attributable to each splicing state of each gene in each cell, where the splicing state is one of spliced (S), unspliced (U) or ambiguous (A).  If ``quant`` was run with a two-column transcript-to-gene map (not in USA-mode), then the resulting count matrix will be a ``C``x``G`` matrix, as splicing status is not tracked.  For more details on USA mode and its uses, please read the ``alevin-fry`` `paper <https://www.nature.com/articles/s41592-022-01408-3>`__ or `preprint <https://www.biorxiv.org/content/10.1101/2021.06.29.450377v1>`__, or the `corresponding tutorial <https://combine-lab.github.io/alevin-fry-tutorials/2021/improving-txome-specificity/>`__.

The ``quants_mat.mtx`` is a matrix market `coordinate format <https://math.nist.gov/MatrixMarket/formats.html>`__ file (or if running with ``--use-eds`` then ``counts.eds.gz`` is a gzipped file in EDS_ format) that stores the gene-by-cell expression matrix. The two other files provide the labels for the rows and columns of this matrix. The ``quants_mat_cols.txt`` file is a text file that contains the names of the rows of the matrix, in the order in which it is written, with one gene name written per line. The ``quants_mat_rows.txt`` file is a text file that contains the names of the columns of the matrix, in the order in which it is written, with one barcode name written per line.
